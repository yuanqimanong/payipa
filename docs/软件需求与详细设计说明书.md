## 0. 术语

| 术语 | 代码 | 含义 |
|---|---|---|
| 主控 | `apps/server`（进程）+ `packages/payipa-core`（业务包） | server 唯一常驻进程（装配/API/WS 接入/调度循环/监控/OpenAPI）；core 是全部业务逻辑，server import 直接函数调用（非网络 API） |
| 子节点 / agent | `packages/pyp-agent` | 独立部署、出站 WS 连主控；抓取 + 直传 + 回传；只依赖 contracts |
| 契约 | `packages/payipa-contracts` | 纯 Pydantic schema（零 I/O、零逻辑），主控与 agent 唯一共同依赖 |
| 工具库 | `jianbing_utils`（独立仓） | 自研开箱即用通用工具库（小而全、静态方法/纯函数；借鉴业界设计思路、不复制第三方代码）；首个模块 s3 分片 |
| 中转 | core.proxy + 可独立部署的代理中转服务 | agent 出网统一经此，提供受控路由、供应商传输故障转移和审计；不改变访问授权边界 |

## 1. 系统概述

**一句话**：payipa 是源无关的「数据获取 → 清洗 → 查询 → 组装 → 推送」一站式数据接入与加工平台。

**主线**：`获取(agent) → [raw 留存] → 解析+清洗 → 入库(data_center) → 查询 → 组装(business) → 推送/对外 API`。

**四条护城河（M0 把接口/边界留好，能力逐阶段增强——非第一天全实现）**：
1. 主控**中心化限流 + 自动调频**（多 agent 不叠加打爆同源）；
2. 用户/AI 代码**断网沙箱 + Query Gateway**（凭证/DB 不进脚本）；
3. **源无关 Connector + Pydantic 强类型契约**（不锁死网页）；
4. **合规访问与受控出口**：标准 HTTP / Playwright 连接器 + 中心限流 + 访问边界暂停 + 代理中转审计。

**架构红线**：见 [00 §3.8](00-总纲与全局约束.md)（10 条，CI/评审对照）。

**数据访问前提**：数据源必须属于自有系统、已授权 API、明确允许自动访问的公开页面，或具备数据提供方的其他明确许可。Connector 遵守服务条款、API 文档、`robots.txt`、认证边界与速率限制；认证失败、授权拒绝、需人工确认的访问挑战或明确拒绝自动访问的响应会暂停数据源并转人工复核，不通过切换账号、会话、出口或地域继续请求。

### 1.1 非功能需求与规模假设（v1 基线，非硬 SLA）

| 维度 | 基线 |
|---|---|
| 规模 | agent 几~几十台，每台槽位 N 数十~数百协程；单源日请求 万~百万级；raw 压缩后 ~30KB/页（10 万页/日≈3GB、100 万≈30GB），默认留 7 天 |
| 数据量 | 单数据源表 千万行级 PG 直扛，更大上原生分区（留后手）；对象存储无上限 |
| 性能 | 控制面消息 KB 级、亚秒下发；查询默认排序走 `(created_at,id)` 索引 P95<200ms；UI 深翻页限 1 万行内，超出走筛选/异步导出；调频用 EWMA 平滑 |
| 可用性 | 单实例起步、升级短暂停机可接受；agent 断线指数退避自愈；Redis/内存队列崩溃从 PG 权威重建 |
| 并发模型 | anyio 单事件循环（server）；沙箱/代理中转按 worker 池并发；**限流是全局资源约束，不是并发目标** |
| 扩展信号 | local 存储吞吐瓶颈→切 S3；单源表过大→分区；中转流量瓶颈→独立部署扩容/局部切选路分配；单队列压力→agent 分组多队列 |

## 2. 总体架构

**部署拓扑（v1）**：

```text
                        ┌──────────────── 浏览器（用户）
                        │  SSR 页面 / HTMX / SSE / 插件点选
                        ▼
┌─────────────────────────────────────────────┐
│ 主控机  apps/server (FastAPI, 单进程)          │
│   = payipa-core: crawl/explore/studio/deliver │
│     /ai/proxy/monitor/storage                 │
│   + Redis(队列/令牌桶/缓存, 可选内存降级)       │
└──────┬───────────────┬──────────────┬─────────┘
       │ WS(控制面,小消息) │ SQL          │ presigned/HTTP
       ▼               ▼              ▼
   agent 机×N        PG 机           对象存储(S3)
   pyp-agent         三库:            大对象/raw/产物
   + sidecar 沙箱     pyp/            (兜底=主控本地盘)
   + 采集引擎         data_center/
   ↓ 出网             business
   代理中转服务(可独立部署) → 各代理商
       │
   主控侧沙箱机(可独立): 组装/推送脚本 worker 池
```

**面分离**：控制面（WS，KB 级消息：注册/心跳/任务/状态/取消）与数据面（对象存储直传、代理中转抓取）**物理分离**；大对象永不过控制面。

**组件职责**：

| 组件 | 职责 |
|---|---|
| apps/server | HTTP API + SSR 页面 + agent WS 端点 + 调度循环 + 监控 API + OpenAPI；装配 core |
| core.crawl | 任务/规则/版型库、调度分发、限流调频、连接器 registry、分流入库 |
| core.explore | 查询、SQL 网关（四件套）、导出 |
| core.studio | 组装、Query Gateway、schema 加法演进、产物装载 |
| core.deliver | 推送组件、outbox 投递、Dataset API、通知机器人 |
| core.ai | 模型接入(PydanticAI)、帮写脚本、系统提示词、LLM Gateway |
| core.proxy | provider 适配器、混合池、中转选路、溯源统计 |
| core.monitor | agent/机器/任务/数据质量 聚合统计 |
| core.storage | s3 后端(presigned/multipart) + local 后端 |
| pyp-agent | 连接、HTTP/浏览器采集、sidecar 沙箱调用、直传、回传、规则缓存 |
| 代理中转服务 | agent 出网统一入口，聚合选路真实代理，记录溯源 |
| 沙箱 worker | 容器+cgroup+进程池，跑签名脚本，经 Query/LLM Gateway 取数 |

## 3. 工程结构与开发环境

### 3.1 双仓布局（回答「proj 目录 + 两项目 + IDE」）

**必须是同一父目录下的兄弟目录**（因 payipa 用 `path = "../jianbing_utils"` editable 引用）：

```text

├── payipa/                   ← monorepo（uv workspace）；IDE 主要加载这个
│   ├── pyproject.toml        （workspace + Python>=3.14）
│   ├── uv.lock
│   ├── apps/server/          （src/pyp_server: main.py + templates/ + static/）
│   ├── packages/
│   │   ├── payipa-contracts/ （src/payipa_contracts: agent/task/rule/artifact/result/monitor/event/version + errors）
│   │   ├── payipa-core/      （src/payipa: crawl/explore/studio/deliver/ai/proxy/monitor/storage）
│   │   └── pyp-agent/        （src/pyp_agent: cli/conn/rules/upload/fetch/sandbox_client）

│   ├── deploy/               （docker compose / Dockerfile / alembic）
│   └── tests/
└── jianbing_utils/           ← 独立仓（Python>=3.11，uv_build，发 PyPI）
    └── src/jianbing_utils/s3/ ...
```

### 3.2 开发方式（你的问题，明确回答）

1. **让 Claude 信任 `proj/` 父目录**（不是只信任 payipa）——这样联调时它能同时改 payipa 和 jianbing_utils。
2. 首次：在 payipa 下 `uv add --editable ../jianbing_utils` → jb 改代码即时生效、**联调期无版本问题**（详见 [00 §2.2 联调流程](00-总纲与全局约束.md)）。**纪律**：提交 payipa 前还原 path 源（不进仓库）。
3. **IDE 加载 payipa 根目录**即可（uv workspace 单一环境）；`uv sync` 装齐，启动 = `uv run uvicorn pyp_server.main:app`（或 compose 起 server+PG+Redis）。jianbing_utils 只需在 `../` 存在即可（editable 指向它）。
4. 是的——**Claude 会在 proj 下新建/维护 payipa 与 jianbing_utils 两个项目**；你用 IDE 开 payipa 做主开发，jb 需要改时切过去或用多根工作区。

### 3.3 依赖方向（import-linter 强制）

```
apps/server → payipa-core → payipa-contracts
pyp-agent → payipa-contracts   (禁止 pyp-agent → payipa-core)
payipa-core 各模块 → 只经公开接口互调；contracts 零依赖(仅 pydantic)
jianbing_utils：被 core/agent 依赖，自身依赖全来自公开 index
```

### 3.4 技术栈：见 [00 §3.7 汇总表](00-总纲与全局约束.md)（此处不复述）。

### 3.5 配置与密钥管理

- **两层配置**：①**启动必需项走环境变量**（PG 三库连接串、Redis、S3 endpoint/ak/sk、加密主密钥）——用 `pydantic-settings` 读 env/.env，dev/prod 分环境；②**运行期可变项走 DB**（公共配置管理页：AI 模型/系统提示词/存储配置/全局默认参数/代理商）。
- **密钥分级**：DB 内存储的凭证（代理商 API / LLM key / 推送目标 / 采集凭证）用 **envelope encryption**——主密钥(KEK) 从 env/KMS 注入、**绝不入库/入仓**，DB 只存密文；对外/接入 token（api_key、join、node、job_token）**存 hash 不可逆**（[03 §定案-11]）。
- 单进程装配：server 启动读 env 建 PG/Redis/S3 连接池 + 加载 cron 大表 + 起调度循环 + 挂 WS/HTTP/SSE 路由。

### 3.6 测试策略

- **单元**：各 package 内 `tests/`，纯逻辑（限流算法、指纹、schema 演进 diff、选路）。
- **契约测试（关键）**：agent↔主控以 contracts 为准——契约变更跑**向后兼容测试**（旧 agent × 新主控握手、字段增删可选默认）；contracts 加 **schema 快照测试**，破坏性变更必须升 `version.py` 才允许。
- **集成**：顶层 `tests/` 跨包——采集全链路（fixture 站点→抓取→raw→清洗→入库）、组装（Query Gateway→沙箱→装载 business）、推送（outbox→重试→死信）。
- **fixture**：规则测试用样本页/响应 fixture（借鉴 clearpage benchmark 思路），M1 起建，供「获取源码测试」与回归复用。
- **CI**：ruff + import-linter + pytest + Py3.14；jianbing_utils 矩阵 3.11–3.14 + `uv build --no-sources` 验证。

### 4.2 `data_center` 采集数据库

| 表 | 关键字段 |
|---|---|
| `data_{source短码}` | id, **data_fingerprint(unique)**, batch_id, created_at, updated_at(timestamptz), state(smallint), owner_id, tenant_id, **fields(jsonb 用户字段袋)**, **field_meta(jsonb: 每字段 raw/normalized/confidence/locator/warnings)**, [勾索引字段→STORED 生成列 + B-tree] |
| `artifacts` | id, bucket, object_key, storage_backend(s3/local), size, sha256, etag, content_type, status, task_id, attempt_id, agent_id, source_id, **owner_id, tenant_id(预留), expires_at(保留期/GC)**, created_at |

- **`data_fingerprint` 唯一性 = 表内**：因**按数据源分表**（每 source 一张 `data_{source}` 表），表内唯一即等价「源内唯一」；owner/tenant 单源一致，**无需组合唯一键**。重复采集靠 `INSERT ... ON CONFLICT (data_fingerprint) DO UPDATE`（刷 updated_at）去重——**去重是设计目标**，非缺陷。
- 加法式演进：新字段进 fields(零 DDL)；勾索引 → `ADD COLUMN ... GENERATED ALWAYS AS (fields->>'x') STORED`（PG11+ 瞬间）；破坏性变更拦截。

### 4.3 `business` 组装产物库

- `asm_{assembly短码}`：结构同 `data_*` 混合 schema（指纹唯一索引 + fields JSONB + 生成列）；由组装脚本产 parquet → 主控装载。

> 跨 database 不 join：组装 = 读 data_center → 写 business（应用层）；查询按单库单表。

### 4.4 状态机

**`requests.state`（smallint，正数=正常态、负数=错误码）**：

| 值 | 态 | 转入 |
|---|---|---|
| 0 | 排队 queued | 建 batch 拆分入队 |
| 1 | 已分派 assigned | Dispatcher 按空闲槽派发 |
| 2 | 运行中 running | agent 领取执行（记 lease_until） |
| 3 | 成功 success | 回报成功、结果入库 |
| 4 | 已取消 canceled | 收 Cancel 帧 |
| <0 | 失败（错误码，见 `errors.py`） | -1 网络 / -2 超时 / -3 访问暂停 / -4 软失败 / -5 解析失败 / -6 节点失联 … |

转换：`0→1→2→3`；失败置负码——**未达 max_retry → 回 0 重试**（退避），**达上限 → 定格负码**；`lease` 超时无心跳 → Reaper 回收（回 0 或标 -6 节点失联，不计业务重试）；任意态收 Cancel → 4。

**`rules.status`**：`draft → testing → active`（内容寻址；draft/testing 仅测试任务引用，active 才被 prod 引用）。
**`batches`**：`running → done | failed | canceled`，stats 汇总（总/成/败/进行/空白率）。
**权威在 PG**：Redis 队列仅运行时视图，崩溃后按 state 重建（0/1/2 未完成的重新入队；lease 过期的回收）。

**跨库写入一致性（无分布式事务）**：一次采集写两库——**先写数据（`data_center`，`ON CONFLICT` 幂等）→ 再置状态（`pyp` 的 requests/batch）**；顺序保证「状态=成功 ⟹ 数据已落」。若数据已写、状态更新失败，请求留 running、被 Reaper 重试，幂等 upsert 不产生重复。组装同理（先写 `business` 再置 assembly 状态）。**规模内不引入分布式事务/重型对账**；可选加一个轻量对账任务（比对 `batch.stats.ok` 与 data_center 实际行数，异常告警）。

## 5. 契约设计（payipa-contracts，Pydantic v2）

> 字段标注**「已生效/未生效」**（红线）；新增字段可选带默认值向后兼容，破坏性变更升 `version.py` 协议号。

| 文件 | 关键模型（字段骨架） |
|---|---|
| `agent.py` | `RegisterReq(agent_id, hostname, capabilities:{automation:bool,...}, slot_n, version)` / `RegisterResp(node_token, contract_version)` / `Heartbeat(inflight:[req_id], free_slots, metrics)` / `TaskAssign(TaskSpec)` / `StatusReport(req_id, state, result_ref?)` / `Cancel(batch_id\|req_id)` / `ErrorFrame` |
| `task.py` | `TaskSpec(task_id, batch_id, source, target, rule_ptr:(rule_id,version,content_hash), channel:test\|prod, group, proxy_config_id, account?, params, priority, timeout, engine_hint:(http\|browser))` |
| `rule.py` | `RulePack(fields:[FieldRule], layout_match:(url_regex, body_regex), crawl_rules, clean_ops)` / `FieldRule(name, locator:(xpath\|css\|jsonpath\|regex), type:store\|link\|store+link, clean:[Op], index:bool)` / `RuleStatus(enum draft/testing/active)` |
| `artifact.py` | `Artifact(bucket, object_key, backend, size, sha256, etag, content_type, status)`（永久 key，无 presigned） |
| `result.py` | `ResultBatch(items:[Item], artifacts:[ArtifactRef], summary:ExecSummary)` / `Item(fields, field_meta:{name:FieldMeta})` / `FieldMeta(raw_value, normalized_value, confidence, locator, warnings)` / `ExecSummary(elapsed, count_ok, count_fail, count_blank, warnings)` |
| `monitor.py` | `NodeSnapshot(agent_id, online, slot_n, slot_used, inflight)` / `QueueStat(by_priority, by_group)` / `BatchProgress(total, ok, fail, running, pct)` / `QualityMetric(parse_ok_rate, parse_fail_rate, blank_rate)` / `ProxyStat(by_egress_domain: success_rate)` |
| `event.py` | `AuditEvent(actor, action, object, before, after, ts)` / `LifecycleEvent(batch_id, type, payload)` |
| `version.py` | `CONTRACT_VERSION`；握手校验 |
| `errors.py` | **错误码枚举（负数）**：如 `-1 网络失败 / -2 超时 / -3 访问暂停 / -4 软失败 / -5 解析失败 / -6 节点失联 ...`（开工第一批定死） |

### 5.1 规则声明式 spec 结构（骨架示例）

`rules.spec`（JSONB）由内置解释器执行；不够用挂 Python 脚本（固定方法名）。骨架：

```json
{
  "layout_match": { "url_regex": "^https://x\\.com/\\w+/status/\\d+", "body_regex": "og:type\" content=\"article" },
  "fields": [
    { "name": "title", "locator": {"type":"css","expr":"h1"},
      "clean": [{"op":"strip"},{"op":"regex_extract","pattern":"(.+)"}], "index": true, "type": "store" },
    { "name": "published_at", "locator": {"type":"css","expr":"time@datetime"},
      "clean": [{"op":"parse_date","default_tz":"Asia/Shanghai"}], "type": "store" },
    { "name": "next", "locator": {"type":"css","expr":"a.next@href"},
      "clean": [{"op":"url_normalize"}], "type": "link" }
  ],
  "crawl": { "strategy": "bfs", "max_depth": 3 },
  "fail_when": { "status_in": [200], "body_contains": ["系统维护","服务暂不可用"] },
  "fingerprint": ["title","published_at"]
}
```

- `type`: `store | link | store+link`；`index:true` → 提升为生成列建索引。
- 清洗算子（工具箱）= 声明式 `op` 列表（strip/regex_extract/parse_date/url_normalize/…），**完整算子清单实现期定**；`parse_date` 用 dateparser、双存原文+timestamptz。
- `fail_when` = 普通可恢复软失败判定（状态码 + 内容特征，命中后按退避策略重试），不能把认证失效、访问拒绝或交互式验证配置为可重试；这些信号由平台内置 `AccessBoundary` 暂停并转人工复核。`fingerprint` = 数据指纹字段组合。

## 6. 核心模块设计（接口级）

- **crawl**：`Scheduler`（cron 触发→建 batch→拆 requests→入队）、`Dispatcher`（按空闲槽派发，[07 槽位制]）、`RateLimiter`（令牌桶 key=(egress×子域×account)）、`Throttler`（AIMD+Retry-After）、`AccessBoundary`（认证/授权/交互式验证信号→暂停+人工复核，[07 §2.5]）、`ConnectorRegistry`（五形态；**爬虫框架 BaseCrawler + SitemapCrawler/ListDetail/Api/Browser 见 [12](12-爬虫框架与接入.md)**）、`RuleStore`（内容寻址）、`Ingestor`（分流：入库 data_center / 生成新 requests）。
- **explore**：`QueryService`（Tabulator remote：filter/sort/page→SQL）、`SqlGateway`（只读角色+statement_timeout+LIMIT 封顶+审计）、`Exporter`（csv/excel/json/parquet，keyset 流式，大导出=任务）。
- **studio**：`Assembler`（触发→建 job）、`QueryGateway`（结构化 table API + job_token JWT + Arrow 流）、`SchemaEvolver`（加法演进）、`Loader`（parquet→business 装载，指纹幂等）。
- **deliver**：`PushComponentRegistry`、`OutboxWriter/Consumer`、`DatasetApi`（Query Gateway 对外版 + api_key）、`Notifier`（lark/email）。
- **ai**：`ModelRegistry`（PydanticAI 多 provider）、`ScriptAssistant`（帮写，系统提示词+库白名单）、`LlmGateway`（沙箱内 ctx.ai 代理，审计+成本）。
- **proxy**：`ProviderAdapter`（tunnel/longlived/iplist）、`MixPool`（选路：轮询/加权/域粘性）、`RelayGateway`（中转转发）、`UsageTracker`（溯源→调频/monitor）、`HealthChecker`。
- **monitor**：`Aggregator`（收 agent 上报+任务统计+质量指标）、`MetricsApi`（喂 06 页 + SSE）。
- **storage**：`StorageBackend`（抽象）→ `S3Backend`(presigned/multipart via jbutils.s3) / `LocalBackend`(流式分块+磁盘水位)。
- **代码执行器抽象**（agent 与主控共用）：`Executor` → `LocalExecutor` / `SandboxExecutor`（本机 sidecar / 远程沙箱端点）。**生产默认 `SandboxExecutor`；`LocalExecutor` 仅开发 / 无沙箱降级**——降级可接受的前提是脚本已经过管理员签名，v1 只承载受信脚本并隔离资源故障（[04A](04A-沙箱执行服务.md)）；是否允许生产降级由部署开关控制，**默认关**。

## 7. agent 设计

- `conn`：出站 WS（join token 接入→注册上报能力/slot_n→心跳带 inflight+free_slots→领任务→回报→收取消）；断线指数退避重连；anyio task group 组织并发，cancel scope 支持整树取消。
- `fetch`：**两类引擎**——`niquests`（常规 HTTP）/ 标准 Playwright（动态渲染、正常交互与已授权登录，需 automation 能力）；按 `engine_hint` 选。全部经**受控出口**（配置一个中转地址），并由统一访问边界策略处理认证、授权与交互式验证信号。
- `rules`：任务带指针→本地内容寻址缓存→未命中拉取验 hash。
- `sandbox_client`：解析/清洗脚本发本机 sidecar（无则本地执行）；按批不按条。
- `upload`：大对象 presigned 直传 S3 / local 走主控接口（jbutils.s3，同一套代码）。
- 纪律：**零 DB 凭证、零 S3 密钥**；只依赖 contracts。
- 依赖成本注：Playwright 浏览器镜像与运行资源需在 Win/Linux 冒烟中评估。**⚠️ 外部依赖的价格/许可证均为调研备注、非设计硬前提，开工前复核**——含 **ProxyCat GPL-2.0**：借鉴其设计思路可以，直接复用其代码需评估许可证影响，或自研/换宽松许可参考。

## 8. 关键流程

1. **采集全链路**：Scheduler 到点→建 batch→拆 requests 入 Redis 队列→Dispatcher 按空闲槽经 WS 下发→agent 领任务→（RateLimiter/Throttler 在主控侧节流下发）→agent 拉规则→选引擎经代理中转抓取→sidecar 解析+清洗（产 items+field_meta+新链接）→大对象直传 S3 回指针→WS 回传 ResultBatch→core.Ingestor 分流：入库 data_center（指纹幂等）+ 新链接生成 requests→更新 batch 统计→SSE 推进度。
2. **限流与访问边界**：见 [07 §2.5](07-任务与调度.md)（慢启动 AIMD + 429/503 减半 + Retry-After + 认证/授权/交互式验证信号暂停 + 熔断）。
3. **取消**：Cancel 帧→清队列中该 batch 未执行 requests + agent 侧 cancel scope 取消在途协程树（优雅收尾回传已抓部分）。
4. **组装**：上游 batch 完成→触发 assembly job→沙箱经 Query Gateway(job_token) 读 data_center→pandas/polars 加工（可 ctx.ai）→产 parquet→presigned 直传→主控 SchemaEvolver+Loader 装载 business（增量=读侧水位+写侧指纹幂等）。
5. **推送**：批次组装完/手动/定时→写 push_outbox→Consumer 取→跑推送组件（主控执行器，出站按目标）→成功标记/失败重试+死信+告警；指纹随数据附带（下游去重）。

### 8.1 贯穿约定

- **correlation id**：全链路共用 `task_id / batch_id / attempt_id`，贯穿 structlog 结构化日志、artifacts、task_events——三者可互相跳转排查。
- **多媒体流**：agent 经代理中转下载多媒体 → multipart 直传 S3 `桶/数据配置UUID/files/文件ID` → 回传指针（不入 raw、不过控制面）。
- **调频状态**：每 `(受控出口 × 子域 × account)` 的当前速率/EWMA 存 **Redis**（内存降级时进程内），可随时重建；访问暂停与熔断状态同源。

## 10. 安全设计

- **三层凭证**：登录鉴权 / 任务数据 token(job_token) / 采集凭证池；用户/AI 脚本**永不接触明文**。
- **token 存 hash**（api_key/join/node token）；代理商/模型/推送凭证**加密存储**、管理员统一配。
- **脚本签名**：管理员统一签名，agent/沙箱验签后执行。
- **出网策略两类（收口，防安全策略打架）**：
  - ①**沙箱脚本（组装/清洗）**：容器+cgroup+断网，egress 白名单**仅 Query Gateway + LLM Gateway**，不能访问任意外网；
  - ②**推送组件**：**不在沙箱**，在主控受控执行器跑，**按目标连接器出网**（飞书/webhook/下游 DB/对象存储），受 **目标域白名单 + 加密凭证 + 审计** 约束。
  - 两者物理分开：组装脚本要的是「只读数据、不出网」，推送要的是「按目标出网、不碰源数据库」。
- **多租户 v1 = 应用层 owner 过滤**（所有查询按 owner_id 过滤）；`owner_id`(+`tenant_id`) 字段就位为**预留**，**PostgreSQL RLS 暂不启用**——留到有真实多租户需求时再开（避免过早增加迁移/查询封装/测试复杂度）。
- **审计**：audit_log 全覆盖。TLS 默认校验。
