## 1. 需求对齐

### 1.1 需求方口述（第 1 轮，2026-07-04）

- apps/server 专职做前端相关呈现，技术栈意向：**Jinja2 + HTMX 2.0.x + Tabulator 6.x + sse-starlette + PyJWT + SQLAdmin 等**——即**服务端渲染（SSR）路线，不建独立 SPA 前端**。
- 对调用关系的理解求证：「server 通过 api 去调用 payipa-core 的 agent/…」→ 澄清见 §1.2。

### 1.2 澄清（助手，同轮）

1. **server ↔ core 不是网络 API 调用**：两者在**同一个进程**里，server `import` payipa-core 后直接函数调用（普通 Python 包依赖），中间没有 HTTP、没有序列化。「API」只存在于三张**对外**的脸：
   - 浏览器 ↔ server：页面（Jinja2）、HTMX 局部刷新请求、SSE 推送；
   - agent ↔ server：WebSocket（帧格式在 contracts）；
   - 外部系统 / AI ↔ server：REST + OpenAPI。
2. **payipa-core 里没有 agent 模块**：agent 是独立包 pyp-agent，部署在**其他机器**上，server 经 WS 与它通信；server 在进程内调用的是 core 的业务模块（crawl / explore / studio / deliver / storage）。contracts 的 `agent.py` 只是 WS 帧的形状定义。
3. ✅ 需求方已确认以上两点与 SSR 栈（2026-07-04 第 2 轮）——定案见 §4。

### 1.3 需求方口述（第 3 轮，2026-07-05）—— 页面清单

登录页、个人页；系统管理员：角色权限、用户管理、公共配置管理、操作日志；任务管理、爬虫规则管理、组装数据管理、推送数据管理、查看数据，等等。

**鉴权模型（定案）**：登录 = **账号密码**（管理员开通、无自助注册）；会话 = **HttpOnly + Secure cookie**（防 XSS，不放 localStorage）；**PyJWT 用于程序化场景**——对外 Dataset API 的 API key、agent join/节点 token、沙箱 job_token。密码哈希用 argon2/bcrypt（库实现期定，倾向 argon2）。

**权限矩阵（基础版，RBAC）**：角色（管理员/技术/运营/运维）× 资源（规则源/任务/查询数据/组装/推送/通知机器人/用户角色/公共配置/节点/日志）× 动作（读/写/执行/授权/导出）。粗粒度：
- **管理员** = 全部；
- **技术** = 规则源/任务/查询/组装/推送 读写执行，系统管理无；
- **运营** = 任务(选能力建/跑)、查看数据、补数修数(强制入库)、通知机器人 读写执行，规则/组装脚本只读或无；
- **运维** = 节点/监控/日志/存储 读(+节点配置写)，业务数据按策略；
- **特殊权限**（可单独授予，叠加在角色上）：如「SQL 查询窗口」「强制入库」——对齐 02/03 的"单独权限"定案。细粒度权限点清单随开发补。

| Jinja2 | 3.1.x | Pallets，稳定（既有知识，未单独核验版本） |

设计要点：

1. **SSR 路线的结构含义**：不需要独立 SPA 与 node 构建链——[00 §3.5](00-总纲与全局约束.md) 的 `frontend/` 目录取消，改为 apps/server 内 `templates/` + `static/`；htmx/tabulator 以 **vendor 静态文件**方式随包分发（离线/内网部署友好，无 CDN 依赖）。
2. **SSE 与 HTMX 天然配**：htmx 官方 SSE 扩展 + sse-starlette 服务端——「前端实时通道 SSE vs WS」由此收敛为 **SSE**（浏览器侧单向推送足够：任务进度、日志滚动；用户操作走普通 HTMX 请求）。
3. **PyJWT 使用注意**：浏览器场景 token 应放 **HttpOnly cookie**（防 XSS 窃取），不放 localStorage；或会话 cookie 为主、PyJWT 用于 API token / agent join token 等程序化场景——鉴权模型细节待本模块后续轮次。
4. **SQLAdmin 边界**：管理员后台与面向用户的业务页面分开挂载，配独立管理员鉴权；Beta 级用于内部工具可接受。
5. **OpenAPI 用途调整**：SSR 定案后「openapi.json → 前端 TS 类型代码生成」失效（无 TS 前端）；OpenAPI 价值保留给 **AI 直读 + 对外 Dataset API**（00 §3.6 链路仍成立）。

## 4. 定案（2026-07-04，详见 [决策记录.md](决策记录.md)）

1. **界面 = 服务端渲染（SSR）**：Jinja2 + HTMX 2.0.x + Tabulator 6.x + sse-starlette + PyJWT + SQLAdmin（内部管理后台）。
2. **取消独立 SPA 前端与 `frontend/` 目录**：界面由 apps/server 内 `templates/` + `static/` 承载；htmx/tabulator vendor 静态文件，无 node 构建链。
3. **前端实时通道 = SSE**（htmx SSE 扩展 + sse-starlette；用户操作走普通 HTMX 请求）。
4. 架构关系确认：server 同进程 import payipa-core 直接函数调用（非网络 API）；agent 为独立部署的 pyp-agent，经 WS 通信。
5. **页面清单 = 4 域**（公共/数据全流程/系统管理/运维），明细见 §1.4；每页映射到对应业务模块。
6. **鉴权 = 账号密码登录（管理员开通）+ HttpOnly cookie 会话**；PyJWT 仅用于 API key / agent token / job_token 等程序化场景。
7. **权限 = RBAC 基础矩阵**（角色×资源×动作）+ 特殊权限叠加（SQL 窗口、强制入库等），见 §1.4。
