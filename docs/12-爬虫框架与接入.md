## 1. 需求对齐（需求方口述，2026-07-05）

1. 需要**爬虫框架 base 类 + 实现类**——**为 AI 帮写**：做一个 **AI 可继承、可补全、可约束**的骨架；人工也可继承。
2. **边界**：基础设施、生命周期、返回格式、错误处理、代理、限速、去重、FieldMeta 由**框架管**；AI 只补具体站点规则（URL、选择器、字段映射、详情页解析）。
3. 实现类举例：`BaseCrawler`、`SitemapCrawler`（自动提取 sitemap 下数据）、`ListDetailCrawler`（列表页+详情页）、`ApiCrawler`（接口型）、`BrowserCrawler`（自动化/登录）等。
4. 支持**接入其他系统的老爬虫**（scrapy 生态、requests 简单爬虫）：**尽可能少改造**其代码即可兼容/接入，然后用平台运维、乃至扩展成一种能力。

## 2. 技术调研（核验 2026-07-05）

| 点 | 结论（一手来源） |
|---|---|
| **HTTP_PROXY 环境变量接管出网** | Scrapy `HttpProxyMiddleware`（默认启用）与 requests（urllib）**都尊重 `HTTP_PROXY/HTTPS_PROXY` 环境变量**——旧爬虫**零代码改造**设个环境变量即走代理中转（docs.scrapy.org settings / httpproxy） |
| **Scrapy 嵌入运行** | `CrawlerProcess`/`CrawlerRunner` 可编程跑 spider；`item_scraped` signal 可在程序内直接拿 item（docs.scrapy.org practices/api）——沙箱内跑旧 spider + 挂平台 pipeline 即接入 |
| **sitemap 库** | **ultimate-sitemap-parser (USP)**（GateNLP）：支持全部 sitemap 格式 + robots.txt 自动发现 + 百万 URL 实测 + `all_pages()` 生成器；advertools `sitemap_to_df` 备选（pypi/github） |
| **旧爬虫托管模式** | Crawlab：语言无关**上传代码 + SDK `save_item` 接入 + 隔离进程执行 + cron 调度**——印证「上传旧代码 + 薄 SDK + 沙箱运行 + 平台调度」成熟（github crawlab） |

## 3. 设计 A：爬虫框架骨架（模板方法模式）

### 3.1 分层：框架管 vs 规则补

| 框架（基类，AI/人不碰） | 子类补（AI/人写） |
|---|---|
| 生命周期、`fetch`（经代理中转/三引擎/限速/去重/重试）、raw 留存、FieldMeta 产出、结果契约、错误处理、上报、correlation id | 起始 URL/sitemap/endpoint、选择器/字段映射、详情页解析、翻页/爬行规则、认证参数 |

框架提供的 SDK（子类内调用）：`self.fetch(url)`（**仅单请求任务内从属子请求**，仍经中转/限流，**不新建调度单元**）/ `self.emit(item)`（产 Item + FieldMeta）/ `self.follow(url)`（**向主控回报新链接**——经 `ResultBatch.discovered` → 主控 URL 指纹去重后入队，非本地入队）/ `self.log` / `self.ctx`（规则指针、参数、账号、代理配置）。

横切语义收窄：**限速** = 经中转由主控集中限流；**去重** = 主控入队（URL 指纹）+ 入库（数据指纹）两道；**重试** = 瞬时网络重试与 [07](07-任务与调度.md) 任务级重试分层、不叠乘。

### 3.2 基类与实现类

- **`BaseCrawler`**（抽象基类）：定义生命周期 + 抽象方法 `start()` / `parse(response)` /（可选）`parse_detail(response)`；框架驱动流程。**映射到 SDD 两层分布式模型（非单体自驱 spider）**：`parse` 为**每响应回调、无跨响应本地状态**；新链接一律经 `self.follow` 回报主控、子请求经 `self.fetch`（见 §3.1），调度单元只由主控经 `ResultBatch.discovered` 去重后新建。
- **`SitemapCrawler`**（**里程碑 M1–M2**）：给 sitemap URL 或 robots.txt → 框架用 **USP 自动展开全部 page URL** → 逐个 fetch → 子类只写 `parse_detail`。即「自动提取 sitemap 下数据」。依赖 **ultimate-sitemap-parser**，**开工前核许可证 + 3.14 兼容（advertools 备选）**。
- **`ListDetailCrawler`**（**里程碑 M1–M2**）：列表页+详情页——子类定义 `list_url`、`item_links(response)`、`parse_detail(response)`、`next_page(response)`；框架管翻页 + 详情调度。
- **`ApiCrawler`**（**API 型 Connector 预留**）：接口型——子类定义 `endpoint`、`params`、`parse_json(data)`、`paginate(data)`；框架管认证（管理员配 key，[02 §定案-8]）、翻页、限速（含 account 维度 [07 §4-17]）。
- **`BrowserCrawler`**（**里程碑 M5**）：自动化/登录——子类定义 `actions(page)`（Playwright 兼容操作）、`parse(page)`；框架管浏览器引擎（CloakBrowser/Playwright）+ 绑代理出口 + 指纹；需 agent **自动化能力分组**（[01 §4-7]/[07 §4-16]）。用于登录模块与动态页。
- 可扩展：`FeedCrawler`(RSS/Atom) 等随需求加。

### 3.3 为什么 AI 不会写飞（可约束）

- AI 只实现基类**抽象方法**（补规则），**签名/返回类型/FieldMeta 契约固定** → 输出结构天然受约束。
- 系统提示词喂：基类清单 + 抽象方法签名 + SDK（fetch/emit/follow）+ 库白名单（[08](08-AI能力.md)）。
- 生成的子类走 **test 通道 fixture 试跑 → 管理员签名 → 发布**（同 [02](02-数据清洗.md)/[08](08-AI能力.md) 轨道，不开新口子）。
- **三档递进，同一执行器**：声明式 JSON spec（最简单站点、无需代码）→ 框架子类（中等复杂、结构化代码、AI 友好）→ 裸脚本（兜底最灵活）。

### 3.4 框架归属（已定，见 §5）

framework 是**执行代码**（不适合放纯 schema 的 contracts）。**已定：独立轻包 `payipa-crawler`（仅依赖 contracts），供 core 与 pyp-agent 同时依赖**——因主控侧 core.ai 负责生成/校验子类、agent 侧执行子类，若 framework 内嵌 pyp-agent 则 core 需依赖 agent、违反 core→agent 禁令；抽出仅依赖最低层 contracts 的独立轻包即避免 core→agent 依赖。

## 4. 设计 B：旧代码接入（最少改造）

里程碑：**legacy 沙箱托管 = M3**（复用组装沙箱设施，[04A](04A-沙箱执行服务.md)）。

### 4.1 三条路径（改造量从小到大）

1. **零改造出网接管**：旧爬虫（scrapy/requests/任意）在沙箱运行，平台注入 **`HTTP_PROXY`/`HTTPS_PROXY` 环境变量**指向代理中转 → 出网自动经中转（限速/溯源/换 IP），**代码一行不改**。（B 中转方案红利）
2. **产出接入（改几行）**：旧代码把「存库/print」改成平台薄 SDK **`emit(item)`**（或约定 stdout JSON 协议 / scrapy item pipeline）→ 数据进平台入库 + FieldMeta。
3. **调度托管**：旧爬虫作为「**外部脚本 Connector**」上传 → 沙箱运行 → 复用平台调度/批次/日志/重试/监控/代理（cron/手动/API 触发，[07](07-任务与调度.md)）。

### 4.2 scrapy 专门支持

沙箱内 `CrawlerProcess`/`CrawlerRunner` 跑 spider；平台注入 settings（代理、`DOWNLOAD_DELAY` 对齐限流、并发）+ 一个平台 pipeline（`item_scraped` signal → emit）。**spider 代码基本零改**——设环境变量 + 挂平台 pipeline 两步即接入。

### 4.3 requests / 简单爬虫

环境变量走代理（零改）+ 产出改 `emit()`（几行）+ 沙箱跑。最简。

### 4.4 边界与演进

- 旧代码在沙箱（防事故隔离）、出网经中转（合规/限速统一；即 [00](00-总纲与全局约束.md) 出网不变量第三类「抓取沙箱：egress 仅放行代理中转（固定入口）」）；但其**去重/重试是它自己的**——「接入即用」得到运维托管，**深度能力（平台 FieldMeta/去重/精细调频）需渐进迁移到 BaseCrawler 子类**才获得。
- 演进路径：**旧代码接入跑起来 → 逐步迁移为 BaseCrawler 子类 → 获得平台全部能力**（乃至「扩展成一种能力」= 发布成数据能力供他人复用）。

## 5. 定案（2026-07-05）

1. **框架骨架 = 模板方法**：`BaseCrawler` + `SitemapCrawler`/`ListDetailCrawler`/`ApiCrawler`/`BrowserCrawler`（可扩展）；框架管横切、子类补规则；**AI 继承补抽象方法、受契约约束、走 test+签名**。
2. **SitemapCrawler 用 ultimate-sitemap-parser** 自动展开 sitemap（robots.txt 自动发现）。
3. **旧代码接入三路径**：HTTP_PROXY 环境变量**零改造走中转** + `emit` SDK 产出接入 + 外部脚本 Connector 沙箱托管调度；**scrapy 用 CrawlerProcess + 平台 pipeline**。
4. 三档采集形态（声明式 spec / 框架子类 / 裸脚本）共用同一代码执行器与轨道。
5. **分布式执行模型（核心）**：`BaseCrawler` = SDD 两层分布式模型（非单体自驱）——`parse` 每响应回调无跨响应本地状态、`self.follow` 经 `ResultBatch.discovered` 回报主控 URL 指纹去重入队、`self.fetch` 仅任务内从属子请求；限速（主控集中）/去重（URL 指纹入队 + 数据指纹入库两道）/重试（瞬时网络 vs 07 任务级、分层不叠乘）横切收窄见 §3.1。
6. **framework 归属 = 独立轻包 `payipa-crawler`**（仅依赖 contracts，供 core 与 pyp-agent 同时依赖，避免 core→agent 依赖）。
7. **里程碑**：`SitemapCrawler`/`ListDetailCrawler` = M1–M2；`ApiCrawler` = API 型 Connector 预留；`BrowserCrawler` = M5；legacy 沙箱托管 = M3。
