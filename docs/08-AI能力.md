## 1. 需求对齐

### 1.1 需求方口述（第 1 轮，2026-07-05）

1. **模型管理**：管理员负责配置若干模型；用户在对应任务界面**选择某个模型**来写代码。
2. **系统提示词**：管理员提前给系统提示词规范 AI 输出；**项目默认提供该提示词，管理员可修改**。
3. **生成约束**：AI 写脚本不是随便写——有**特定的格式、方法调用、参数标准**等；只能在**允许的库依赖**中引用方法。
4. **依赖管控**：如果要增加新库，需要**管理员增加 docker 镜像分支**，沙箱才能执行。

### 1.2 整理（助手，同轮）

- **闭环**：AI 生成的脚本与人写的脚本走**同一条轨道**——固定方法 SDK + 库白名单约束 → test 通道试跑验证（不入正式库）→ 管理员签名发布。AI 只是「写得快的技术人员」，不开新口子。
- **系统提示词的内容源**：平台固定方法清单、参数标准、库白名单、输出格式约定——与教人写脚本的文档同源维护（改 SDK 时提示词同步更新）。
- **模型接入抽象**：多模型配置（管理员级凭证）建议经 PydanticAI（多 provider 统一接口，00 已核验就绪）；具体接入协议（OpenAI 兼容 / Anthropic / 本地推理）留实现期。

## 4. 定案（2026-07-05，详见 [决策记录.md](决策记录.md)）

1. **管理员配置模型清单**（凭证管理员级）；用户任务/配置界面按需选择模型。
2. **系统提示词**：项目默认提供、管理员可修改。
3. **生成约束**：固定格式/方法调用/参数标准 + **库白名单**内引用；生成脚本与人写脚本同轨（test 试跑 → 签名发布）。
4. **新增依赖 = 管理员构建新 docker 镜像分支**，沙箱方可执行。

> **修订（2026-07-05）**：AI 生成脚本**仅 Python**（js 已去除，04A 拍板）。AI 写的抓取逻辑脚本同样进沙箱执行（agent 侧 sidecar 横向扩展消化脚本量）。

### 4.5 LLM Gateway（运行期，汲取自 [04A §定案-8](04A-沙箱执行服务.md)）

> **实现回写（2026-07-11，以代码为准）**：LLM Gateway + provider 抽象 + Anthropic 一等实现**已落地**（`payipa.ai` 的 `gateway.complete` / `registry`（register/list/resolve/set_default/set_enabled + 系统提示词）/ `provider`），REST 见 `routers/ai.py`(`/api/llm/{models,prompts,complete}`) 与 `routers/config_mgmt.py`（模型登记/启停/设默认、系统提示词编辑 UI）。**未采用 PydanticAI**——改为**自研 `LLMProvider` Protocol + 官方 `anthropic` SDK（AnthropicProvider）+ EchoProvider（离线无 key 冒烟）**。成本/审计当前落库 `pyp.audit_log`（`action=llm.call`，挂 model/provider/task_id/token/cost）；**Langfuse 自部署**为后续。沙箱脚本 `ctx.ai()` 运行期入口仍待随沙箱执行接线。

沙箱脚本 `ctx.ai()` 经 LLM Gateway 出网调 AI 的运行期口径（区别于 §定案-1 的管理员配置期）：

- **模型路由**：`ctx.ai()` 的选型走 §定案-1 管理员配置的模型清单（**ModelRegistry**）——Gateway 只按 registry 路由，不自行接管凭证与选型。
- **运行期模型来源**：脚本/数据源配置新增「**AI 模型**」字段指定本次用哪个模型；**缺省取平台默认模型**（管理员在 ModelRegistry 标注默认项）。
- **成本/审计**：每次调用挂 `task_id`/`owner` 记录成本 + 调用审计。**当前实现**落库 `pyp.audit_log`（`action=llm.call`）；**Langfuse 自部署**接入为后续（与 04A「审计与成本记录」口径一致）。
- **模型凭证**：沿用 **SDD envelope encryption（信封加密）**，key 留平台侧、脚本不接触明文（与 04A「key 留平台侧」一致）。

## 5. 遗留问题

- **LLM Gateway + provider 抽象 + Anthropic 一等实现已落地**（自研 `LLMProvider` Protocol + 官方 anthropic SDK + Echo 离线 provider，未采用 PydanticAI）。剩余开放项：其他 provider 接入协议（OpenAI 兼容 / 本地推理）、沙箱 `ctx.ai()` 运行期接线、Langfuse 自部署。
- AI 交互形态细节（对话式改写 / 一键生成 / 报错自动修复循环）随界面细化。
- MCP 化（让 AI 调平台 API）：候选 FastMCP，需求出现时立项。
