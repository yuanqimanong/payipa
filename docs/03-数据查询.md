## 2. 技术调研

> 核验 2026-07-04（Tabulator 官方文档经搜索核验、PG 分页基准文章、既有知识标注）。

### 2.1 Tabulator 组合筛选/排序能力（回答口述-4）：全部具备

- **头部筛选**（headerFilter）：每列筛选输入；**组合条件**：`setFilter` 传过滤器数组 = AND；数组内再嵌数组 = OR，可多层嵌套（官方文档示例：age>52 AND (height<142 OR name=steve)）。
- **多列排序**：`setSort` 传排序对象数组（或 shift 点击）。
- **关键：远程模式**——`filterMode:"remote"` / `sortMode:"remote"` / `paginationMode:"remote"` 时，筛选/排序/页码参数随 Ajax 发给服务端，服务端返回 `{last_page, data}`。**与 SSR 架构正配**：服务端把参数译成 SQL（系统列直译；JSONB 字段用表达式；勾选「需索引」的走生成列索引）。（tabulator.info/docs/6.x）
- 提示：「全字段可筛可排」在 JSONB 字段上是表达式查询（无索引时顺序扫描）——单源单表+中等数据量可接受；量大的字段引导用户勾「需索引」（02 已定机制）。

### 2.2 用户 SQL 的包装与守护（回答口述-2）：可行，业界标准做法

你说的「加个包装」正确，完整四件套：

1. **子查询包装分页**：用户 SQL 不写分页，执行层包一层——`SELECT * FROM ( <用户SQL> ) AS q LIMIT 100 OFFSET n`（或按选定列 keyset）；
2. **只读防线**：SQL 功能走**独立 PG 只读角色**（仅对授权数据表有 SELECT 权）+ 事务级 `READ ONLY`——写操作在数据库层面就不可能；
3. **语句超时**：会话级 `statement_timeout`（如 15–30s），慢查询自动杀，防拖库；
4. **强制行数上限**：包装层 LIMIT 封顶（如 1 万行）；要全量走**异步导出任务**（复用 07 任务体系）。

加分项：执行前 `EXPLAIN` 成本预检、每次执行记入操作日志（接 §2.5 审计）。（PG statement_timeout/权限为官方标准能力，既有知识）

### 2.3 分页：keyset O(1) vs offset O(n)（回答口述-5）

- 基准数据：offset 深翻页线性劣化——千万行表 OFFSET 首页 8ms、10 万级深页 **8 秒**（扫描并丢弃全部跳过行）；**keyset（游标式，`WHERE (排序列,id) > (上页末值)`）任意深度恒定 ~0.9ms**，且并发插入不重不漏；有基准称深页差距达千倍级（citusdata、sequinstream、stacksync 等）。
- keyset 局限：**不能跳页**（只能顺序翻）、需要「排序列+id」复合索引、任意字段排序时索引要跟上。
- **建议组合**：UI 翻页用 **offset + 深度上限**（Tabulator remote 分页天然页码式；默认最新排序走 `(created_at,id)` 索引；限制可浏览深度如 1 万行内，超出提示用筛选收窄或导出）；**导出与对外 API 用 keyset 流式**（全量、恒速、不重不漏）。

### 2.4 任务关联研判（回答新题 A）：三层方案，运营只见「开关+数字」

1. **能力参数化（必做，直接解掉 10/15 页问题）**：技术发布数据能力时定义**运行参数**——名称、说明、类型、默认值、**上限**（如「页数：默认 10，最大 50」）；运营建任务 = 选能力 + 表单填参。你说的「在数据任务上增加可供用户显示参数的配置」——对，就是这个，且这是自动化平台的标准形态（模板+参数）。同一能力从此不用为改个数字复制。
2. **链式模板（推荐）**：链在**技术侧预定义**——技术在能力 B（评论）上声明「可承接能力 A（发帖）的输出：字段映射 A.帖子ID → B.种子参数」；运营建任务选了 A 后，界面自动出现「**＋追加流程：获取评论（取前 N 个帖子）**」，勾选 + 填 N 即可。**运营看到的是一个开关和一个数字，不是流程图**——理解成本最低。执行层完全复用 07：A 批次产出 → 触发 B 任务实例，血缘键串联（07 任务界面本就要求血缘）。
3. **自由 DAG 编排（不做）**：n8n 式画布对运营过重；真正的深度组合走 04 组装（技术写脚本）。
- 三层不互斥：技术也可以把「A→B 模板」固化发布成一个更傻瓜的组合能力入口（即你现在的方案），供最不想动脑的场景。

### 2.5 用户生命周期 / 权限 / 审计研判（回答新题 B）

- **停用而非删除**：账号只可停用（软删）——登录即刻失效、名下周期任务**默认暂停并告警**（避免无主任务静默跑，待确认）。
- **资源所有权与交接**：所有资源（任务/数据配置/组装/分组）带 owner；管理员走**交接向导**批量转移（可按业务分组筛选）；**删除前置校验：名下有资源 → 只能停用，交接完成才可删（或永远软删）**——正是「有任务的用户不能删」。
- **操作日志**：`audit_log`（操作者/时间/动作/对象/关键前后值/来源），覆盖任务增删改跑停、规则发布、强制入库、SQL 查询、权限变更、交接迁移；保留期可配。**契约形状落位 contracts `event.py`（00 §3.6 本就预留审计事件）**。
- **权限粒度**：角色（管理员/技术/运营）× 资源类型（数据能力/任务/数据集/组装/系统设置）× 动作（读/写/执行/授权）——矩阵在 [06](06-界面.md) 细化。

### 2.6 时间处理（回答第 2 轮，核验 2026-07-04）

- **系统时间（created_at/updated_at）= timestamptz**：PG 官方 wiki 明确「不要用 timestamp without time zone」——timestamptz 存的是 **UTC 瞬时**（2000-01-01 起的微秒数），任意时区写入自动归一 UTC；显示按会话时区或 `AT TIME ZONE 'Asia/Shanghai'` 转换（wiki.postgresql.org / Don't Do This）。「存 UTC、按东八查和显示」正是其原生机制：应用层统一 UTC，展示层（Jinja 过滤器或 SQL AT TIME ZONE）转东八。`ON CONFLICT DO UPDATE` 刷新 updated_at、保留 created_at。
- **业务时间（页面解析出的时间）= 双存，不做破坏性转换**：
  1. **原文 str 永远保留**（保真，来源即真相，随时可重新解析）；
  2. 旁存**解析后的 timestamptz（可空）**用于筛选排序，解析失败置空、原串仍在——「怕转不回来」由此消解：转换是加法不是替换；
  3. 解析组件进 02 清洗工具箱：**dateparser 1.4.1**（2026-06-15，Zyte/Scrapinghub 维护——爬虫出身、专为 HTML 页面时间设计：200+ locale、中文相对时间「3天前」、时区处理；classifier 含 3.14）（pypi.org/pypi/dateparser）；
  4. **无时区信息的按「数据源级默认时区」解析**（源配置项，默认东八）；带时区的按其时区归一 UTC。

## 4. 定案（2026-07-04，详见 [决策记录.md](决策记录.md)）

1. **查询视图以任务为中心**：用户任务页（一次性/周期/指定日期、选数据能力）→ 批次日志/完成度 → 查该任务产出数据（默认最新，可筛可排）。
2. **查询边界 = 按数据源单表**；跨表只在 04 组装；全字段可筛可排（量大字段引导勾「需索引」）；行详情竖向展示。
3. **界面 = Tabulator remote 模式**（AND/OR 组合筛选、多列排序、页码分页，参数发服务端译 SQL）。
4. **SQL 查询 = 单独权限 + 四件套**（子查询包装分页、只读角色、语句超时、行数封顶）+ 执行记审计。
5. **分页组合**：UI 翻页 offset + 深度上限（默认最新排序走 `(created_at,id)` 索引）；导出/对外 API keyset 流式；导出 csv/excel/json/parquet，大导出走异步任务。
6. **分析下沉**：平台只做简单组合加工；深度分析经 API 推下游专业系统；数据集与对外 Dataset API 挂组装产物查看页（04/05）。
7. **任务关联三层**：能力参数化（运行参数：默认值/上限）+ 技术侧链式模板（A 输出→B 种子，运营勾选填参）+ 不做自由 DAG——回填 07/contracts。
8. **系统时间 = timestamptz（UTC 瞬时）**，created_at/updated_at 全数据表标配，展示按东八转换。
9. **业务时间双存** = 原文 str 保真 + dateparser 解析 timestamptz（可空）；无时区按数据源默认时区（默认东八）解析。
10. **用户生命周期**：停用不删、交接向导批量转移 owner、名下有资源不可删、停用用户周期任务默认暂停并告警、audit_log 全覆盖（形状落 contracts event.py）。
11. **凭证 token 存 hash + 行级多租户预留（汲取点⑥，2026-07-05 纳入）**：API key / join token / job_token 等一律**存 hash 不存明文**（比对用 hash）；所有业务数据行预留 `owner_id`(+`tenant_id`)，为将来 RLS/计量/审计铺垫（与 [02 §定案-11](02-数据清洗.md) 一致）。**v1 = 应用层 owner 过滤，PostgreSQL RLS 暂不启用**（字段就位、留有真实多租户需求时再开）。
