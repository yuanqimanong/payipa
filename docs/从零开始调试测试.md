# 从零开始调试测试（PyCharm 手把手）

> 目标：**一台全新的干净机器**上，从装环境到用 PyCharm 断点调试跑通「主控 + 采集 agent」全链路，
> 按本文顺序照做即可**一次过**。覆盖到当前已实现的功能（M0 骨架 + M1 单源端到端 + 登录/建源 + M2 派发环）。
>
> 命令示例给出 **Windows PowerShell** 与 **macOS/Linux** 两种；只需照抄自己平台那一行。
> 术语：**主控 = pyp-server**（FastAPI，Web 界面 + API + agent 接入 + 后台派发环）；**agent = pyp-agent**（采集节点，出站连主控）。

---

## 0. 先看懂要跑什么

一次完整调试会同时跑起两类进程（同一台机器即可）：

| 进程 | 是什么 | 怎么起 | 依赖 |
|---|---|---|---|
| **pyp-server**（主控） | FastAPI，监听 `:8000`，提供网页/API/`/ws/agent` 接入 + 每秒派发环 | PyCharm 跑 `uvicorn pyp_server.main:app` | PostgreSQL 三库 |
| **pyp-agent**（采集节点，可多个） | 出站 WebSocket 连主控，领任务→抓取→回传 | PyCharm 跑 `python -m pyp_agent.cli join …` | 只连主控，**零 DB / 零密钥** |

数据流：浏览器建源 → 主控建批次（请求落库 `QUEUED`）→ 派发环把请求发给空闲 agent → agent 抓取→回传 → 主控入库 `data_center` → 网页查看。

**启动顺序（重要）**：PostgreSQL → 建 3 个库 → 配 `.env` → `uv sync` 装依赖 → `alembic` 建表 → 建管理员 → 起主控 → 起 agent → 验证。

## 1. 安装前置软件

### 1.1 Git
- Windows：装 [Git for Windows](https://git-scm.com/download/win)。
- macOS：`xcode-select --install` 或 `brew install git`。
- Linux：`sudo apt install git`。
> 必须有 git：既要 clone 代码，`uv sync` 还会用 git 拉取依赖 `jianbing-utils`（见 §5）。

### 1.2 uv（Python 包/环境管理器，会自动装 Python 3.14）
- Windows PowerShell：
  ```powershell
  powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```
- macOS/Linux：
  ```bash
  curl -LsSf https://astral.sh/uv/install.sh | sh
  ```
装完**重开一个终端**，验证：
```bash
uv --version
```
> 本项目锁定 **Python 3.14**。你不必手动装 Python——`uv sync` 会按 `requires-python>=3.14` 自动下载对应解释器。
> （想提前装：`uv python install 3.14`。）

### 1.3 PostgreSQL（14+，推荐 16）
- Windows：装 [EDB PostgreSQL 16](https://www.postgresql.org/download/windows/)，安装时记住 **postgres 超级用户的密码**、端口默认 **5432**。
- macOS：`brew install postgresql@16 && brew services start postgresql@16`。
- Linux：`sudo apt install postgresql-16`，确保服务已启动。

验证能连上（会提示输密码）：
```bash
psql -h localhost -U postgres -c "select version();"
```

## 3. 建 3 个数据库

项目用**同一个 PostgreSQL 实例下的三个库**：`pyp_sys`（平台）/ `data_center`（采集数据）/ `business`（组装产物）。用超级用户建库：

```bash
psql -h localhost -U postgres -c "CREATE DATABASE pyp_sys;"
psql -h localhost -U postgres -c "CREATE DATABASE data_center;"
psql -h localhost -U postgres -c "CREATE DATABASE business;"
```
> 库名可改（见 `.env` 的 `PG_DB_*`），但**必须先手动建库**——`alembic` 只建表、不建库。
> 也可用 pgAdmin 图形界面右键 Databases → Create。

## 4. 配置 `.env`

在 `payipa/` 目录下把模板复制成 `.env` 并改密码/密钥：

- Windows PowerShell：`Copy-Item .env.example .env`
- macOS/Linux：`cp .env.example .env`

用编辑器打开 `payipa/.env`，**至少改这几项**：

```ini
PG_HOST=localhost
PG_PORT=5432
PG_USER=postgres
PG_PASSWORD=你的postgres密码        # ← 改成第 1.3 步设置的密码
PG_DB_PYP=pyp_sys
PG_DB_DATA_CENTER=data_center
PG_DB_BUSINESS=business

PYP_SERVER_SESSION_SECRET=请改成一段至少32字节的随机串xxxxxxxxxxxxxxxx   # ← 会话签名密钥，≥32 字节
UPLOAD_SECRET=也改成一段随机串                                       # ← 内部上传令牌 HMAC 密钥

DATA_ROOT=var/storage      # 本地 raw 落盘目录（自动创建，已 gitignore）
RAW_RETENTION_DAYS=7
```
> `.env` 已被 `.gitignore` 排除，**不会入库**，放心填真实密码。
> 主控会从**当前工作目录**读取 `.env`——所以后面 PyCharm 运行配置的「工作目录」务必设为 `payipa` 根（§8）。

## 8. PyCharm 配置

### 8.1 打开项目并选解释器
1. PyCharm → **Open** → 选 `payipa` 目录（**不是**它的父目录）。
2. **File → Settings → Project: payipa → Python Interpreter → Add Interpreter → Add Local Interpreter → Existing**，选：
   - Windows：`payipa\.venv\Scripts\python.exe`
   - macOS/Linux：`payipa/.venv/bin/python`
   （§5 的 `uv sync` 已生成 `.venv`。PyCharm 2024.2+ 也能自动识别 uv 环境。）
3. 确认右下角解释器显示为该 `.venv`。

### 8.2 主控 server 运行/调试配置
**Run → Edit Configurations → 左上 `+` → Python**，按下表填：

| 字段 | 值 |
|---|---|
| Name | `server` |
| 运行目标 | 选 **Module name**（不是 Script path），填 `uvicorn` |
| Parameters | `pyp_server.main:app --host 127.0.0.1 --port 8000` |
| Working directory | `payipa` 根目录（即 `$PROJECT_DIR$`） |
| Python interpreter | 上面的 `.venv` |

> **调试要点**：**不要加 `--reload`**。`--reload` 会另起一个子进程做热重载，PyCharm 断点打在子进程里不会命中。
> 需要断点就用上面的配置（无 reload），点 **Debug**（虫子图标）启动；只想自动热重载、不打断点时再加 `--reload` 并用 Run 启动。
> `.env` 会因「工作目录=payipa 根」被自动读取，无需在 PyCharm 里重复填环境变量。

### 8.3 采集 agent 运行/调试配置
再建一个 Python 配置：

| 字段 | 值 |
|---|---|
| Name | `agent-a` |
| 运行目标 | **Module name**：`pyp_agent.cli` |
| Parameters | `join --server http://127.0.0.1:8000 --token dev --agent-id dev-a` |
| Working directory | `payipa` 根目录 |
| Python interpreter | 同一个 `.venv` |

> `--token dev` 仅是 dev 模式的本地兼容入口；production 必须从节点管理页签发短时、单次入网码。
> `--agent-id dev-a` 便于调试时区分进程；正式运行默认从 `--state-dir` 的身份文件读取稳定 UUID。
> agent 不连数据库，无需 `.env`。

### 8.4 多 agent（可选，测派发/上线）
复制 `agent-a` 配置成 `agent-b`，把参数改成 `--agent-id dev-b`（可再加 `--slots 2` 控制并发槽）。
两个 agent 一起 Debug 起来，主控派发环会把任务在两者空闲槽间铺满。

## 9. 启动与冒烟验证

**按顺序**（前置 §1–§7 已完成）：

1. **起主控**：在 PyCharm Debug 运行 `server`。控制台出现 `Uvicorn running on http://127.0.0.1:8000` 与 `dispatch loop up …` 即成功。
   - 浏览器开 `http://127.0.0.1:8000/docs` 能看到 OpenAPI；`http://127.0.0.1:8000/api/agents` 返回 `[]`（暂无节点）。
2. **起 agent**：Debug 运行 `agent-a`。控制台出现 `joining http://127.0.0.1:8000 …`。
   - 刷新 `http://127.0.0.1:8000/api/agents`，应出现一个节点：`[{"agent_id":"dev-a","online":true,"slot_n":4,...}]`。
3. **走一遍业务（浏览器）**：
   1. 打开 `http://127.0.0.1:8000/` → 自动跳登录 → 用 `admin` + §7 的密码登录。
   2. 「＋ 新建数据源」→ 表单已预填 books.toscrape.com 示例：填**短码**（如 `books`）→「创建并运行」。
   3. 自动跳到 `/data/books`，Tabulator 表格里看到抓取结果（表头筛选 / 点列头排序 / 翻页均走服务端）。
4. **或走 API（不用登录）**：
   ```bash
   # 触发一次采集
   curl -X POST "http://127.0.0.1:8000/api/sources/books/run" -H "content-type: application/json" --data @deploy/examples/books.json
   # 看进度（batch_id 取上一步返回值）——running 递减、ok 递增、pct→100
   curl "http://127.0.0.1:8000/api/monitor/batches/1"
   # 看排队深度
   curl "http://127.0.0.1:8000/api/monitor/queue"
   ```
   > Windows 若用 PowerShell 的 `curl`（实为 Invoke-WebRequest），建议改用 `curl.exe ...` 或直接用浏览器 `/docs` 里的 “Try it out”。

至此，一台干净机器已完整跑通「登录 → 建源 → 派发 → 采集 → 入库 → 查看」。

### 9.5 多波爬行（discovered links）验证

跟进链接采集：规则里给字段设 `type: link` 或 `store+link`（其值即待跟进 URL），并加 `crawl: {max_depth: N}`（**不设 crawl ⇒ 只抓种子、不跟进**）。agent 解析每页收集这些链接回传 `ResultBatch.discovered`；主控按 URL 指纹去重后**并入同一批次**入队（深度=父+1、≤max_depth），派发环继续抓——种子完成时批次不会提前收尾，会等整波抓完。

一次验证（1 个种子页 → 跟进其 20 条详情链接，共 21 请求）：
```bash
curl -X POST "http://127.0.0.1:8000/api/sources/mwave/run" -H "content-type: application/json" -d '{
  "seed_urls":["https://books.toscrape.com/catalogue/page-1.html"],
  "indexed_fields":["title"],
  "rule":{"item_locator":{"type":"css","expr":"article.product_pod"},"crawl":{"max_depth":1},
    "fields":[{"name":"title","locator":{"type":"css","expr":"h3 a@title"},"type":"store"},
      {"name":"detail_url","locator":{"type":"css","expr":"h3 a@href"},"type":"store+link","clean":[{"op":"url_normalize"}]}],
    "fingerprint":["title"]}}'
# 轮询：total 会从 1 跳到 21（种子完成→发现 20 条并入同批），批次不会在种子完成时就收尾
curl "http://127.0.0.1:8000/api/monitor/batches/<batch_id>"
```
预期：`total` 由 1 增长到 21、最终 `ok=21` 批次 done；`data_center` 落 20 条唯一书目（详情页用列表规则→不产额外行，多版型/按 URL 分规则属后续切片）。要观察去重/深度：`enqueue_discovered` 打断点，或直接查库 `SELECT depth, count(*) FROM requests WHERE batch_id=<id> GROUP BY depth`（应为 `{0:1, 1:20}`）。

### 9.6 优先级 / 定时(cron) / 取消 验证

- **优先级**：建源表单/`tasks.priority` 为 high/mid/low，派发环按 (优先级, 深度, 入队序) 排序——高优先请求插队先派。`/api/monitor/queue` 的 `by_priority` 按档位分桶显示排队深度。
- **定时(cron)**：给某任务在 `schedules` 表登记 `cron_expr` + `enabled=true`（`next_run_at` 留空即立即到点）；派发环每 tick 调 `fire_due_schedules`，到点就用**建源时存档的种子**(`tasks.params.seed_urls`)建新批次并用 cronsim 推进 `next_run_at`。断点打 `scheduler.py:fire_due_schedules`。
- **取消**：`curl -X POST http://127.0.0.1:8000/api/batches/<batch_id>/cancel` → 排队请求就地置 CANCELED、在途请求收到 `Cancel` 帧后 agent 取消协程树并回报 CANCELED、批次 running→canceling→（在途收尾后）canceled。验证：取消后 `/api/monitor/batches/<id>` 的 `running` 归 0；无 agent 连接时可直接观察排队清零（`canceled_queued` = 清掉的排队数）。
- **节点注册/加权分组**：agent 连上即在 `agents` 表 upsert（`status=online`、刷新 `last_heartbeat`/能力/槽位；长期凭证 hash 仅**首次入网**签发落库，凭证重连不轮换）；断连置 `offline`。agent 身份是身份文件里的稳定 UUID（`~/.pyp-agent/identity.json`，`--state-dir` 可改），不再默认主机名。`/api/agents` 看在线节点。加权/分组派发暂无 UI——直接改库：`UPDATE agents SET weight=5, group_name='automation' WHERE agent_id='dev-a';` 令该节点权重更高/归入某组；任务侧 `tasks.group_name` 与之匹配才会派给该组（不匹配则排队等同组节点），`group_name` 为空的任务可派给任意节点。

### 9.7 数据推送（M4：outbox + Consumer + 对外 Dataset API）验证

推送**不经 agent**，全在主控：`push_outbox` 表（状态机 pending→inflight→sent|dead）+ 后台 **Consumer 环**（`consumer.py:consumer_loop`，挂 lifespan，默认开，测试环境 `PYP_SERVER_PUSH_ENABLED=0` 关）。推送组件 = 第三类脚本（内联源码 + 目标域白名单 + 发布签名），丢**隔离子进程**跑（`pushexec.py`，env 擦洗掉 PG_*/CRED_KEK，只注入 payload 行 + 解密后的目标凭证 + 白名单）。

- **对外 Dataset API**：先跑通一次组装（§见 M3）产出 `asm_<短码>`；再签发 API Key（scope 限定可读产物短码）——暂无 UI，用 Python：
  ```python
  # uv run python
  import asyncio; from payipa.db.engine import get_engine; from payipa.deliver.dataset import create_api_key
  print(asyncio.run(create_api_key(get_engine("pyp"), name="demo", datasets=["<短码>"])))  # 明文只打印这一次
  ```
  然后 `curl -H "x-api-key: pyp_xxx" "http://127.0.0.1:8000/api/datasets/<短码>?limit=50"` → `{rows, next_cursor}`；错 key→401、越权产物→403。断点：`routers/datasets.py:get_dataset` / `deliver/dataset.py:read_dataset`。
- **推送组件端到端**：登记+发布一个组件（`code` 含固定方法 `push(ctx)`，用 `ctx.http.post` 出网、`ctx.creds` 取注入凭证），入 outbox，Consumer 一轮排空即投递。最快用 `tests/test_push_deliver_pg.py` 观察（它本地起一个 HTTP 下游、验证收到行 + 状态转 `sent` + 白名单越界被拦 + 未签名组件被签名门拒→退避→dead）。断点：`deliver/component.py:make_component_deliverer`（签名门 `assert_component_runnable`、凭证解密、载荷解析）→ `deliver/pushexec.py:run_push_component`（起子进程）→ `deliver/_push_child.py:_run`（子进程里 exec 组件、白名单校验 `_WhitelistedHTTP._check`）。
- **凭证信封（KEK，红线9）**：目标凭证/机器人 config 以 Fernet 密文入库（`security/secrets.py:encrypt_json`），只有主控 Consumer 侧用 `.env` 的 `CRED_KEK` 解密后注入子进程；子进程无 KEK、无 DB。断点：`security/secrets.py:decrypt_json`。
- **三触发**：①手动——`POST /api/push/components/<id>/enqueue`（body `{rows:[...]}` 内联 / `{product_code}` 数据集增量，可带 `idempotency_key`）返回 `{enqueued}`（0=幂等命中）；`POST /api/notify/<bot_id>/test`（body `{title,text}`）发测试通知。②链路自动——批次由 running→done 的**那一次**收尾即触发：任务 `tasks.params` 里配了 `push_component_id`+`product_code` 就入 outbox 一条 `batch-<id>` 增量推送、配了 `notify_bot_id` 就发收尾通知（`成功 N/总`）。③定时——见 §9.6 cron（推送组件内容自定，含系统状态）。断点：`routers/ws.py:_ingest_result`(`finalize_batch_if_done` 返回 True 处) → `triggers.py:on_batch_finalized`（读 `crawl/run.py:batch_trigger_context`）。自动触发全 best-effort：通知/入队失败只记日志，绝不回滚采集入库。

> **调试子进程断点**：推送组件跑在 `sys.executable` 拉起的**子进程**里，PyCharm 主调试会话的断点不会命中子进程内的 `_push_child.py`。要调组件执行逻辑，直接对 `deliver/pushexec.py:run_push_component`（父侧，看拼好的 spec / 子进程返回）打断点；或临时把组件代码抠出来在单测里直接 `_run(spec)` 调（同进程，断点即中）。

| 想调试 | 在哪个进程 | 建议断点位置 |

## 11. 常见问题（FAQ）

- **断点不生效** → 十有八九加了 `--reload`。去掉它（§8.2），用 Debug 启动。
- **`/api/agents` 一直是空** → agent 没连上：确认 server 已起、`--server` 地址端口对、防火墙没拦 8000；看 agent 控制台是否报连接错误。
- **`sqlalchemy … could not connect` / 密码错误** → 检查 `.env` 的 `PG_*`，确认 PostgreSQL 已启动、三库已建（§3）、密码正确。
- **`uv sync` 拉 `jianbing-utils` 失败** → 确认能访问 GitHub、git 已装；公司网络可能需代理。
- **多个 agent 只显示一个 / 互相顶掉** → 同机多 agent 必须各带不同 `--agent-id`（§8.3）。
- **`alembic … upgrade head` 报库不存在** → 先建库（§3），alembic 不建库只建表。
- **端口 8000 被占** → 改 `--port`（如 8010），agent 的 `--server` 同步改端口。
- **提交任务后没动静** → 确认 server 控制台有 `dispatch loop up`；`dispatched` 恒为 0 是正常的（派发交给后台环，不在建批次时同步发生）。
- **Windows：改 `deploy/alembic.ini` 或 `.importlinter` 后报 `UnicodeDecodeError`** → 这两个文件必须保持纯 ASCII（工具用系统 GBK 编码读取），别往里写中文。

想用容器运行 Agent，见 [../QUICKSTART.md](../QUICKSTART.md) §4。要点：
