## 1. 需求对齐

### 1.1 需求方口述（第 1 轮，2026-07-05）

- 现状用**隧道代理**；本轮升级为**代理中转 / 混合 IP**。
- 本模块**汇总各种代理**：隧道代理、长效代理、返回一堆列表的**固定 iplist**；**每个接入代理商给的 API 单独配置逻辑**——混合起来「**混合 IP 代理**」就出世了。
- 也可以**单独用某个服务商的代理直接用**（如 xxx 的隧道代理），配到后台成为一个选项。
- **都配到后台成为选项，数据任务规则配置时可下拉选择。**
- 记录**使用情况、溯源、IP 使用次数、成功/失败率**等。
- 管理员权限；proxy 页单独成 core 下一个模块。

### 1.2 研判 · provider 适配器 + 混合池（定案方向）

- **三类 provider 适配器**（统一接口，如 `acquire_egress(target) -> Egress`）：
  1. **隧道型**：一个固定入口 endpoint，每次连接由代理商侧换 IP（现状用的这种）；
  2. **长效型**：固定 IP + 时效，到期续订/更换；
  3. **iplist 型**：调代理商 API 拉一批 IP，本地维护列表 + 轮换 + 健康检查。
- **每代理商一个 adapter**（封装其 API、认证、拉取/续期/计费差异）；新增代理商 = 加一个 adapter。
- **混合池**：聚合多个 provider 的出口成统一池，按策略选出口 → 这就是「混合 IP」。
- **单一直用**：也可把某个 provider 单独作为一个「代理配置」选项（不混合）。
- **产出 = 「代理配置」条目**（混合池 / 单一 provider / 不用代理），供 02 数据源规则下拉选。

### 1.3 待确认 + 溯源统计

1. **出口数据面 = B 中转网关（2026-07-05 定）**：agent 只连一个**中转地址**，中转背后聚合选路 → 真实代理 → 目标。理由：溯源/统计天然集中、agent 零代理配置、代理商凭证不出中转、与「代理中转」口述一致，且 ProxyCat/malenia/majora 均验证此模式（§2）。**中转做成可独立部署的服务**（像沙箱，按需扩容）以应对流量瓶颈；个别大流量源（多媒体）若压力大，再评估局部切「选路分配直连」。
2. **溯源与统计**（定）：每次请求记 `provider / 出口 IP / 目标域 / 成败 / 耗时 / 状态码`；聚合出 **IP 使用次数、per-IP 成功失败率、per-(出口×域×account) 成功率**——直接喂 [07 调频](07-任务与调度.md)（选出口/封禁换出口）与 [monitor](09-部署运维.md)。出口健康：连续失败降权/剔除 + 健康检查。可回答「这条数据用哪个 IP 抓的」。

## 2. 技术调研（参考项目提炼，核验 2026-07-05）

需求方给的参考项目，提炼可借鉴设计：

| 项目 | 语言 / License | 定位 | 可借鉴 |
|---|---|---|---|
| **ProxyCat** | Python / GPL-2.0，2.5k★ | 代理池中间件：短效代理 → 固定入口 | **懒获取**（仅请求时才取新代理，省配额）；失效自动验证切换；多选路模式（顺序/随机/自定义）；HTTP+SOCKS5 双协议；一次部署永久用 |
| **malenia / ProxyCompose** | Java+MySQL / 非商业开源 | 代理 IP 二次组合网关：多源采购 → 统一账密+端口 | **多源聚合 + 统一入口**；权限与计量分离；计费/溯源明细 |

**结论**：三者都验证了「多源短效 → 统一固定入口（中转）」是成熟模式——**强化 §1.3-1 方案 B（中转网关）**；**ProxyCat 是 Python 侧最直接参考**（借鉴其懒获取/失效切换/选路模式；⚠️ **ProxyCat 为 GPL-2.0，直接复用代码有传染性**，倾向借鉴思路自研中转层，或评估许可证影响——价格/许可证均开工前复核）。吸收要点：懒获取、内存级故障转移、多协议(HTTP/SOCKS5)、多选路模式、per-出口计费溯源。provider 适配器/健康检查/令牌桶限流为常规实现（限流复用 pyrate-limiter）；中转网关若走 B，Python 侧可用 anyio TCP/HTTP 转发。

## 3. 可行性验证

- ⏳ POC：一个隧道 adapter + 一个 iplist adapter 接入、混合池选路 + 溯源统计打通；中转网关（若 B）吞吐与并发压测。

## 4. 定案（2026-07-05）

1. **proxy = payipa-core 下模块**；管理员配置、代理商凭证加密存储（公共配置管理页）。
2. **provider 适配器三类**（隧道/长效/iplist）+ **混合池** + **单一直用**；每代理商一 adapter。
3. **产出「代理配置」下拉项**，02 数据源规则选用（混合池 / 单一 provider / 不用代理）。
4. **溯源统计**：per-IP 使用次数/成功失败率、per-(出口×域×account) 成功率（补 account 维度，对齐 SDD/D55）→ 喂 07 调频与 monitor；出口健康降权/剔除。**中转独立部署时**定「中转→主控」的计数/明细回报路径（复用 agent 计数管道或专用内部 API，明细落 pyp 溯源表）。
5. **自动化 session 绑出口**：CloakBrowser「bring your own proxy」→ 反检测浏览器会话的 proxy 指向中转地址 + 传 sticky session key，中转保证同会话粘同一上游 IP（见 [01 自动化](01-数据获取与Agent.md)）。
6. **出口数据面 = 中转网关（B）**：agent 连一个中转地址，中转聚合选路 → 真实代理 → 目标；中转可独立部署、按需扩容；溯源统计天然集中。
7. **中转选路**（已采纳）：agent 侧 HTTP CONNECT 的 `Proxy-Authorization` username 段编码 `config_id`，中转据此选对应代理配置的池并选路；「不用代理」映射为 **passthrough 出口**（中转直连目标、不选上游）；**M5** 在 contracts 补 proxy schema + `rule.proxy_config_id`，task 携带该引用下发。
